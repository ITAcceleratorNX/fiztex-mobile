# fiztex-mobile

Рабочий код приложения — `mobile/`. Правила API, дизайн-системы и структуры
описаны в `CLAUDE.md`; прототипы `app/` и `export/` не менять для исправления RN.

## Загрузка данных и повторные запросы

- API вызывается через `mobile/src/shared/api/client.js` и методы `*Api.js`.
- Зависимости эффекта загрузки должны меняться только при изменении параметров
  запроса: токена, id, даты, фильтра, `enabled`. Не передавать свежий объект
  options, результат хука или callback без `useCallback` в зависимости эффекта.
- Для нового периодического опроса использовать
  `mobile/src/shared/hooks/useForegroundPolling.js`: только активное приложение,
  пауза после завершения запроса, очистка таймера и подписки. Видимость раздела
  задаётся через `enabled`; скрытый смонтированный экран не должен опрашивать API.
- Если таймер, обновление и нажатие могут совпасть, объединять запросы с одинаковым
  контекстом, пока ответ не пришёл. Команды записи автоматически не повторять.
- Ответ прошлого аккаунта, ребёнка или фильтра не должен менять новые данные
  или запускать переход. На смене контекста и размонтировании инвалидировать
  запросы; данные прежнего контекста скрывать сразу.
- В `Notifications.addPushTokenListener` использовать полученный `devicePushToken`:
  передавать его в `getExpoPushTokenAsync`, не вызывать из listener
  `getDevicePushTokenAsync` (SDK снова вызовет listener). Объединять повторные
  события того же токена, сохранять последнюю реальную смену при запросе в полёте.
  Проверять этот сценарий тестом с событием native SDK: на вебе и iOS-симуляторе
  регистрация push может быть пропущена, и отсутствие запросов там не доказывает
  отсутствие цикла на телефоне.
- Перед завершением запускать `npm --prefix mobile test`. Для новой загрузки
  добавить проверку в `mobile/scripts/verify-request-lifecycle.cjs` или отдельный
  `verify-*.cjs`: обычные перерисовки не отправляют запросы, нужное изменение
  параметра/ручное обновление отправляет, поздний ответ не перезаписывает данные.

Обычный SQL-запрос к `accounts` на бэкенде проверяет действительность сессии.
Не устранять нагрузку отключением этой проверки или кэшированием прав без
корректного отзыва сессий. Число SQL-строк в dev-логах не равно числу HTTP-запросов.
