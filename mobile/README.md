# fiztex — мобильное приложение (React Native + Expo)

Перенос веб-прототипа fiztex на React Native. Сборщик — Metro (встроен в Expo).
Три роли: ученик, родитель, учитель. Навигация — React Navigation (стек авторизации + вкладки по роли).

## Требования

- Node.js, совместимый с React Native 0.86: 20.19.4+ в ветке 20, 22.13+ в ветке 22 или 24.3+ в ветке 24, и npm
- Приложение **Expo Go** на телефоне (App Store / Google Play), либо эмулятор Android (Android Studio) / симулятор iOS (Xcode, только macOS)

## Установка и запуск

```bash
cd mobile
npm install
npx expo start
```

Если при старте Expo сообщает о несовпадении версий пакетов с текущим SDK, выровняйте их одной командой:

```bash
npx expo install --fix
```

После `npx expo start`:

- отсканируйте QR-код камерой (iOS) или из приложения Expo Go (Android);
- либо нажмите `a` — запуск в Android-эмуляторе, `i` — в iOS-симуляторе, `w` — в браузере.

## Структура

```
mobile/
  App.js                      точка входа: шрифты + темы + состояние + навигация
  src/
    theme/tokens.js           бренд-цвета Fiztex
    theme/ThemeContext.js     light/dark палитры (замена CSS-переменных), useTheme()
    data/mock.js              демо-данные (расписание, предметы, кружки, ивенты и т.д.)
    state/AppState.js         глобальное состояние прототипа (ДЗ, кружки, звёзды, тосты)
    components/               дизайн-система (Hex, Icon, Card, Pill, Avatar, кнопки, шапки)
    navigation/               RootNavigator + вкладки и стеки по ролям
    screens/                  экраны: auth / student / parent / teacher
    features/entrance/        вступительные тесты (код → тест → результат)
```

## Вступительные тесты

На welcome-экране кнопка **«Вступительный тест»**. Flow (API `/api/admissions/*`):

1. Ввод персонального кода → `POST /api/admissions/access-code/verify`
2. Подтверждение ФИО («Это я» / «Данные неверные»)
3. Список назначенных тестов → выбор → экран инструкции
4. «Начать тест» → `POST /api/admissions/attempts/start` (таймер стартует здесь)
5. Прохождение: автосейв, фото с камеры, таймер с бэка, античит-события
6. Экран «завершено» — без баллов (результат после проверки школой)
7. «Посмотреть результат» — только когда бэкенд выставил `OPEN_FOR_VIEWING`

Сессия (токен + attemptId) хранится в AsyncStorage — resume после перезапуска приложения.

Бэкенд по умолчанию: `https://bestsauda.kz`.
Для локального бэкенда: `npm run start:local` или
`EXPO_PUBLIC_API_URL=http://192.168.x.x:8080 npx expo start`.

Перед тестом запустите бэкенд: `cd fiztex-back && ./gradlew bootRun`.

## Обновление Android-приложения через Google Play

Для Google Play нужен **`.aab` (Android App Bundle)**. Сборка через Expo EAS
выполняется в облаке: Android Studio и локальный Android SDK для неё не нужны.
Реальный проект находится в `fiztex-mobile/mobile`, а не в папке прототипа `app`.

### 1. Проверьте приложение и предыдущий номер сборки

Откройте [Google Play Console](https://play.google.com/console/), выберите
существующее приложение PhysTech и перейдите в **Тестирование и выпуск → Последние
выпуски и наборы** (Test and release → Latest releases and bundles).
В списке App Bundle найдите максимальный **код версии / versionCode** среди всех
каналов, включая тестовые. Например, `1.0.0 (3)` означает версию `1.0.0` и код `3`.
Опубликованный выпуск также можно открыть через **Тестирование и выпуск → Рабочая
версия → последний выпуск → сведения об App Bundle**.

Package name должен быть `kz.fiztex.app` — это `expo.android.package` в `app.json`.
Обновление загружается в существующее приложение, новую карточку создавать не нужно.
EAS должен использовать прежний Android keystore / upload key. Если он отсутствует
или Google сообщает о несовпадении сертификата, восстановите прежний ключ либо
пройдите процедуру сброса upload key в Play Console; случайный новый ключ для
обновления не подходит. Ключи и пароли не добавляйте в Git.

### 2. Откройте терминал и проверьте вход в Expo

Из корня монорепозитория:

```bash
cd fiztex-mobile/mobile
npm ci
npm install --global eas-cli@24.7.0
eas whoami
```

Если входа нет, выполните `eas login`. Нужен аккаунт с доступом к организации
`zhubanyshzhs-team` и уже подключённому проекту `fiztex`
(`c92d2e10-65b4-46e3-a128-35304ba9da57`). Повторный `eas init` не нужен.

### 3. Подготовьте номер версии и проверьте код

В `app.json` увеличьте **`expo.version`**, например с `1.0.0` до `1.0.1`.
Именно это значение используется как видимое пользователю имя версии Android.
Поле `version` в `package.json` относится к npm-пакету и не задаёт версию в Google Play.

В этом проекте `eas.json` использует `appVersionSource: remote` и
`production.autoIncrement: true`. Поэтому **versionCode хранится в Expo и
увеличивается автоматически**, а видимая версия `expo.version` меняется вручную.

```bash
eas build:version:get --platform android --profile production
npm test
npx expo install --check
npx expo export --platform android --output-dir /private/tmp/fiztex-android-check
```

Если текущий код в Expo равен `3`, следующая production-сборка обычно получит `4`.
Её код должен быть выше максимального кода, уже загруженного в Play Console.
Если в Google Play есть код выше текущего в Expo, перед сборкой выполните:

```bash
eas build:version:set --platform android --profile production
```

Введите максимальный код из Play Console; при следующей сборке EAS увеличит его.
Не уменьшайте код в Expo, если он уже выше кода в Google Play.

Проверьте, что `.env`, `.env.local` и production-окружение EAS не направляют
`EXPO_PUBLIC_API_URL` на локальный сервер и не включают `EXPO_PUBLIC_API_LOCAL=1`.
Без переопределений используется `https://bestsauda.kz`.

### 4. Соберите подписанный AAB

```bash
eas build --platform android --profile production --non-interactive --freeze-credentials
```

Команда загружает текущие файлы проекта в Expo, автоматически повышает versionCode
и использует сохранённый ключ подписи. `--freeze-credentials` не даёт незаметно
изменить ключи; при отсутствии подходящего ключа сборка завершится ошибкой.
Профиль `production` явно задаёт `distribution: store` и `buildType: app-bundle`.

Дождитесь статуса **Finished** и скачайте `.aab` по ссылке из терминала либо из
[списка сборок Expo](https://expo.dev/accounts/zhubanyshzhs-team/projects/fiztex/builds).
Если терминал закрылся, проверьте уже запущенную сборку, чтобы не создавать лишнюю:

```bash
eas build:list --platform android --limit 5
eas build:view BUILD_ID
```

Папка `android/` здесь локальная и исключена из Git. EAS создаёт Android-проект
заново из `app.json`; не собирайте обновление командой `./gradlew bundleRelease`
из старой локальной папки: в ней может быть старый versionCode и debug-подпись.
Профили `preview` и `apk` предназначены для отдельной установки, а для Google Play
используется `production`.

### 5. Загрузите и проверьте обновление в Google Play

1. В существующем приложении откройте **Тестирование и выпуск → Тестирование →
   Внутреннее тестирование**. Если уже есть черновик выпуска, откройте его для
   редактирования; иначе нажмите **Создать выпуск**.
2. Загрузите `.aab`, проверьте имя и код версии, добавьте описание фактических изменений.
3. Сохраните и внедрите тестовый выпуск, добавьте тестировщиков и откройте ссылку
   участия в тестировании на Android-телефоне.
4. Обновите установленную через Google Play старую версию. Проверьте запуск,
   сохранение сессии, вход, основные разделы и push-уведомления.
5. После проверки продвиньте этот же набор в **Рабочую версию / Production**
   либо создайте рабочий выпуск и выберите его через **Добавить из библиотеки**.
6. Проверьте ошибки Play Console, выберите процент внедрения и отправьте изменения
   на проверку через **Обзор публикации**. Если включена управляемая публикация,
   после одобрения отдельно опубликуйте готовые изменения.

Внутренний тест доступен только тестировщикам. Для остальных пользователей кнопка
**«Обновить»** появится после одобрения и фактической публикации рабочего выпуска,
если их устройство, страна и этап внедрения подходят под условия релиза.
Автоматическое обновление зависит от настроек Google Play пользователя.
Сама сборка AAB ничего не публикует; окно внутри приложения с предложением обновиться
потребует отдельной реализации.

### Если Google Play сообщает о неправильном ключе

Совпадение package name и увеличение versionCode не заменяют проверку подписи.
Сертификат AAB должен совпадать именно с **сертификатом ключа загрузки**,
зарегистрированным в Play Console. Совпадение с предыдущей сборкой Expo само по
себе этого не гарантирует: первая версия могла быть собрана другим разработчиком.

При подготовке версии `1.0.1 (4)` Google Play ожидал SHA-1
`02:BF:BF:A3:51:BD:41:12:22:15:CB:DE:4E:34:58:62:3E:26:6E:9B`, а текущий
keystore в Expo имел SHA-1
`31:C6:A4:4F:3D:F3:45:7E:1F:78:A3:74:16:6A:4F:B2:82:06:4D:6C`.
Эта сборка требует восстановления прежнего ключа либо регистрации текущего
ключа загрузки в Google Play; повторная сборка с тем же keystore ошибку не исправит.

**Если прежний ключ сохранился:** получите у разработчика файл `.jks` / `.keystore`,
alias и пароли через защищённый канал, проверьте его SHA-1 и подключите подходящий
ключ через `eas credentials --platform android` → `production` → управление
keystore. Приватный ключ и пароли храните вне Git. После этого подпишите обновление
правильным ключом.

**Если прежний ключ утрачен:** владелец или администратор приложения может
запросить сброс **ключа загрузки** в Play Console и зарегистрировать текущий
ключ Expo. Для этой версии публичный сертификат подготовлен локально:
`dist/PhysTech-upload-certificate.pem` (SHA-1 `31:C6:…:4D:6C`).
Он содержит только публичный сертификат, без приватного ключа и паролей.

Откройте [Защищено Google Play](https://play.google.com/console/u/0/developers/app/protect-with-play),
выберите PhysTech и перейдите к управлению подписанием приложений.
В блоке **Сертификат ключа загрузки** выберите **Отправить запрос на сброс ключа
загрузки** и приложите PEM. Причину укажите по фактической ситуации: например,
утрата ключа или отсутствие доступа к нему при передаче проекта.
После одобрения Google и наступления указанной даты активации можно повторно
загрузить тот же AAB, если его versionCode ещё не был принят Google Play.
Сброс ключа загрузки сохраняет ключ подписи приложения, которым Google подписывает
обновления для установленных приложений.

## Темы

Светлая/тёмная тема следует системной по умолчанию; переключатель — в профиле любой роли.

## Заметки по переносу

- Веб-примитивы (`div`/`span`/`svg`) переписаны на `View`/`Text`/`react-native-svg`.
- CSS-переменные заменены палитрой темы через `useTheme()`.
- Градиенты — `expo-linear-gradient`. Шрифт Onest — `@expo-google-fonts/onest`.
- Кастомная стековая навигация прототипа отображена на React Navigation.
